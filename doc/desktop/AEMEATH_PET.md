# 爱弥斯 Windows 桌宠

爱弥斯桌宠由 Amadeus 桌面进程管理，使用同一个实时对话页面、ASR、Codex 或原有 Agent、以及现有 TTS。没有独立的桌宠服务或第二条 LLM 会话。

## 启用

1. 按 [Windows 一键启动说明](windows-quick-start.md) 启动应用和后端，在设置中的「本地 3D 模型」导入自行准备且有权使用的 GLB。
2. 打开「实时对话」→「Agent 设定」，勾选「显示爱弥斯 3D 桌宠」。托盘菜单也可以开关桌宠。
3. 在「设置」中确认后端地址及语音引擎；若要让角色随回复开口，在 Agent 设定中开启「自动朗读回复」。Codex 模型仍由实时对话页面选择。

桌宠左键拖动，双击招手，右键打开小面板。面板的「开始 / 结束语音」使用实时对话页面现有录音流程；输入框把文本送入同一会话。「打开实时对话」会显示 Amadeus 主窗口。透明区域允许鼠标穿透；窗口位置保存在 Electron 用户数据目录。

## 实现边界

- 公开版不包含第三方角色模型。用户选择的 GLB 经过校验后复制到本机应用数据目录，由主窗口和桌宠共享。模型必须包含贴图；普通静态 GLB 可显示，口型和动作依赖相应形态键、骨骼。
- `frontend/desktop/pet.html` 是独立的透明渲染页面；`electron/main.ts` 创建 Windows 置顶无边框窗口，`pet-preload.ts` 只开放桌宠所需 IPC。
- 实时对话将聆听、识别、思考、朗读、情绪和回复摘要传给桌宠；嘴部动作跟随实际朗读状态。明确的挥手、移动、转身、跳舞指令触发本地短动作。Agent 回复开头明确表示“我挥手 / 我跳舞”时也能触发相应动作。动作是展示动画，不代表物理或接地验证。
- 关闭主窗口但保留后台运行时，桌宠仍在；完全退出 Amadeus 时，桌宠一同退出。非 Windows 平台不创建桌宠窗口。

## 开发检查

在 `frontend/desktop` 执行 `npm install`、`npx tsc --noEmit`、`npx tsc -p tsconfig.node.json`、`npx vite build`。Windows 下再打开 Electron，实际检查模型透明背景、桌宠右键面板、托盘开关、主窗口中的语音与连接错误提示。

语音识别、LLM 回复和 TTS 的端到端检查需要本机 Amadeus 后端及相应模型或服务就绪。桌宠自身不会尝试绕过这些配置。
