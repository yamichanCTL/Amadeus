# FormalASR-1.7B 接入与本机验证

## 完成内容

- 独立 `formalasr` 引擎，默认 `TaurenMountain/FormalASR-1.7B`。
- 现有模型管理、加载、录音及文件转写接口可选该模型。
- 默认中文、CUDA BF16，支持模型目录、设备、精度、生成 token 上限配置。
- 书面化输出保留原生标点，不返回伪造的词级时间戳，不注册为流式引擎。

- 修复共用 Qwen 适配器在 Windows 重开临时 WAV 的文件锁问题。

## 实际 HTTP 识别

输入由 Windows Microsoft Huihui Desktop 本地合成，7.167 秒：

> 嗯，那个，我们明天下午三点开会，请你提前准备一下材料。

模型两次均返回：

> 我们明天下午三点开会，请你提前准备一下材料。

| 项目 | 实测 |
|---|---:|
| 模型加载请求 | 11.799 秒 |
| 首次识别 HTTP 请求 | 16.443 秒 |
| 同一音频预热后请求 | 0.588 秒 |
| 预热后 ASR 时间 | 0.554 秒 |

实际返回 `engine_used=formalasr`、`segments=[]`、`llm_outputs=null`。
未配置本次请求的 LLM 选项，未调用文本模型/API 服务，未启用上传音频调试归档。
已有应用数据库照常保存本地转写记录。
原始本机测试报告为被 Git 忽略的 `.runtime/formalasr-smoke.json`。

这是一段合成语音的接入验证，不是对真人口音、数字、人名、改口和长语音的质量评测；
也不能用这一条预热时延宣称所有输入都可在 0.6 秒内返回。

## 补测：语义改口和撤回（用户反馈后）

同一天使用 Windows Huihui 合成 6 条完整短音频；经已部署 HTTP 接口识别，
关闭 VAD、热词、二次标点和 LLM。所有音频不足 7 秒，不触发长音频分块。

| 输入 | 实际输出 | 该样例判断 |
|---|---|---|
| 今天上午，不对，今天下午我去买了个东西。 | 今天上午不对，今天下午我去买了个东西。 | 未删除旧时间 |
| 今天上午我去买了个东西，不对，是今天下午。 | 今天上午我去买了个东西，不对，是今天下午。 | 未合并纠正 |
| 我今天要去买手机，刚才那句不要了，我今天去买菜。 | 我今天要去买手机。刚才那句“不要了”，我今天去买菜。 | 未执行语义撤回 |
| 嗯，那个，今天下午我去买了个东西。 | 今天下午，我去买了个东西。 | 去填充词成功 |
| 今天上午我去买了东西，今天下午我把东西退了。 | 今天上午我去买了东西，今天下午我把东西退了。 | 未撤回事实保留成功 |
| 我花了三百块，不对，是三十块，买了一个杯子。 | 我花了三百块，不对，是三十块，买了一个杯子。 | 未删除旧金额 |

另外在独立进程用相同 BF16 权重、官方 qwen-asr 0.0.6 直接推理，
在 `context` 中加入明确“删除被纠正内容、保留最后确认内容”的指令，
对同 6 条音频复测：上述 4 条改口/撤回样例仍全部失败。未将该实验提示词写入应用配置。

本机原始结果：`.runtime/formalasr-selfrepair/results.json` 和 `context_results.json`。
这是有限的合成样例，不能推断所有真人语音的成功率；但已复现用户报告，
说明当前权重的去填充词能力不能等同于可靠的语义改口/撤回能力。
当前接入与作者空 context 配方一致，短句也未被切段；不是少打开一个已知功能开关。
