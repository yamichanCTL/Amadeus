# 艾米斯数字人已接入 Amadeus 实时对话

## 体验入口

运行 `scripts/start_amadeus_digital_human.ps1`，打开已编译的 Windows 应用实时对话页。当前构建位于 `frontend/desktop/release-digital-human/win-unpacked/Amadeus.exe`，使用固定的 `.runtime/digital-human-profile` 配置目录，避免被仍在托盘里的旧版本接管启动。

- **试听口型**：播放本地测试音，走与实时模型相同的 24kHz PCM 播放和口型链路，不请求在线模型。
- **开始全双工**：使用页面中选择的实时语音模型；当前体验配置为 Gemini Live。
- **半身／全身视角**：主页面便于看嘴部；Windows 透明无边框置顶桌宠维持全身。
- 桌宠同步当前回复，主窗口最小化后仍可随声音动嘴。

测试后已退出使用假麦克风的验证进程，重新启动正常设备版本。正式体验进程没有远程调试端口或假麦克风参数。现有后端 `http://127.0.0.1:8000` 健康检查正常，本轮不需要修改或重启后端。

## 接入内容

1. 从 Blender v03 独立导出 `public/pet/aemeath-digital-human.glb`：12 个直接可控形变，包括五元音、眨眼、笑容和嘴角。原几何、UV、蒙皮、987 joints、44 材质分片、19 张贴图与旧运行时资产精确一致；原文件保留。
2. WebSocket 输出 PCM 按实际排程和设备播放时钟提取音量／频带，形成约 30 Hz 的口型帧；预缓冲和静音不开口，设备尾音播完后才结束。
3. WebRTC 输出、普通生成 TTS 文件增加真实音频观察器。浏览器内置 `speechSynthesis` 不提供可访问 PCM，仍不驱动口型；开启音频转播器的特殊 TTS 路由本轮也未接入。
4. 主模型与桌宠共享 `MouthController`：五元音混合、短过渡、取消立即归零、250ms 失联闭口、拒绝旧 epoch／旧时间戳。删除原先由 speaking 状态触发的正弦张嘴。
5. IPC 只传有界口型参数，不传音频或凭据。React 以 ref 传递音频帧，不以每帧状态更新重绘整页。
6. 修复试听取消／卸载后的迟到请求以及旧 TTS 结束事件影响新会话的竞态。

## 验证

- 前端及 Electron TypeScript 检查通过。
- 7 个测试文件共 **58 项通过**：播放时钟、设备尾窗、取消、旧包、重连、界面卸载、生成 TTS、IPC、控制器和现有实时会话回归。
- Vite 生产构建与 Windows 目录包生成成功。
- 真实打包应用中两处模型均加载 12 形变；读取实际 `morphTargetInfluences`，确认试听时两处数值随声音变化。
- 停止试听后两处权重归零，500ms 后旧音频未重新开口。本轮记录一次 UI 停止到观察到闭口约 8ms，**不是模型语音打断或声学延迟指标**。
- 主窗口最小化后，桌宠实际嘴部权重继续变化。
- **真实 Gemini 返回音频**：通过现有后端连接，发送一句短测试文本，两处模型均由返回音频驱动；停止朗读后闭口并结束会话。测试使用静音假麦克风，未录制用户语音。
- 主应用与桌宠截图均实际查看。证据：`.runtime/digital-human-integration/`，精简验收数据保存在 `assets/digital_human/aemeath/v03/runtime_integration_report.json`。

验证脚本：`scripts/digital_human/verify_desktop_integration.cjs`。默认只走本地 PCM；`--live` 仅用于明确以假麦克风启动的本机验证应用。复测时端口使用 9231，不连接用户 Chrome。

## 当前边界

当前是 **真实音频驱动的近似多口型**，不是精准中文音素识别或唇读对齐。实时模型语义、音素、动作意图的更深结合仍属后续阶段。未声称本次已覆盖全部提供商实际调用、长时间稳定性或 10 分钟性能验收。

Blender 离线样片仍可单独编辑；运行时不自动播放离线动画片段，也未新增头发或衣服物理。
